Who Uses It — Job Roles & Real Test Cases
👩‍💻Developer
fgctl scan .
Test case: add a new npm dependency, scan flags it as typosquatted before the commit lands. VS Code shows the finding inline as you type.
🛠️DevOps / Platform Engineer
fgctl scan . --ci --fail-on=high --format=sarif
Test case: a PR opens, CI pipeline fails the build on a critical finding, SARIF results show up natively in the GitHub Security tab.
🛡️Security / AppSec Engineer
fgctl policy set block_typosquatting=true
Test case: org-wide policy rejects a known-bad package automatically; SBOM + Sigstore provenance attached to every release artifact for audit trail.
📡SOC Analyst
Dashboard → Risks / Attack Surface / Alerts
Test case: new CVE lands in a scanned dependency, dashboard surfaces it with a risk grade, analyst triages without touching the CLI.
🚨Incident Responder
fgctl scan --remote user@suspect-host
Test case: a prod box is flagged suspicious — SSH in, pull its package.json/go.mod, scan, get a full finding report. No agent installed, nothing left behind.
📋Compliance / GRC
fgctl sbom npm/pkg@1.0.0 --format cyclonedx-json
Test case: auditor asks "prove what's in this release" — SBOM + SLSA provenance answers it in one command, no manual inventory spreadsheet.
🌍Community Contributor
fgctl intel new · validate · test
Test case: someone spots a new supply-chain attack pattern, authors a detection signature via PR, it ships to every user via fgctl update.
